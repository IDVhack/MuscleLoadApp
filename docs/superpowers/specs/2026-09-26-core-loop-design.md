# Plan B2: Core Loop (Recovery Dashboard + Workout Logging) — Design

Дата: 2026-09-26
Статус: согласован, готов к реализации

## 1. Контекст

Plan B1 построил фундамент: XcodeGen-проект, macOS CI, SwiftData-модели
(`WorkoutSessionRecord`, `SetEntryRecord`, `CustomExerciseRecord`,
`UserProfileRecord`), мост `WorkoutRepository` к `MuscleLoadCore`, пустой
3-табовый каркас навигации. Plan B2 — первая версия с реальной функциональностью:
пользователь может залогировать тренировку и увидеть её на карте
восстановления. Это основной цикл, ради которого всё затевалось.

Справочник упражнений с поиском/своими упражнениями (Plan B3) и история/
статистика/уведомления (Plan B4) — в этот план не входят.

Ссылки: [спека приложения](2026-09-25-muscle-load-app-design.md),
[дизайн фундамента](2026-09-26-ios-foundation-design.md),
[план фундамента](../plans/2026-09-26-ios-foundation.md).

## 2. Решение по визуализации карты восстановления

Изначально планировалась анатомическая схема тела (спереди/сзади,
как в референсном приложении). После нескольких неудачных попыток
нарисовать её через SVG-координаты (агент не может визуально
проверить результат так же, как человек — даже с самопроверкой через
браузер несколько итераций не дотянули до нужного уровня) — принято
решение **отложить анатомическую иллюстрацию** и в Plan B2 показывать
карту восстановления **списком**: 13 строк (по одной на группу мышц),
каждая — название, цветной индикатор статуса, процент восстановления.
Список сортируется по `recoveryPercent` по возрастанию (наименее
восстановленные — сверху). Иллюстрация — отдельная будущая задача
(готовый лицензированный векторный ассет или работа дизайнера).

## 3. Окружение

Без изменений от Plan B1: разработка на Windows без Mac, вся верификация
через `MuscleLoadApp CI` (`macos-14`) и `MuscleLoadCore CI` (`ubuntu-latest`)
в GitHub Actions, проверяется вручную через браузер, а не на слово агента.

## 4. Экран «Главная» — карта восстановления

**`RecoveryViewModel`** (в `MuscleLoadApp/Features/Recovery/`):
- `@Observable` класс, хранит `statuses: [MuscleRecoveryStatus]`.
- `load()` вызывает `WorkoutRepository.currentRecoveryStatuses(asOf: .now)`,
  сортирует по `recoveryPercent` по возрастанию.
- Вычисляемая рекомендация (`recommendationText: String`): если у большинства
  (>50%) мышц `status == .early` → «сегодня лучше отдых или лёгкая активность»;
  если у большинства `status == .ready` → «можно тренироваться»; иначе —
  нейтральный текст про смешанное состояние.

**`RecoveryView`**: список 13 строк (`MuscleRecoveryRow`: название на русском
через `MuscleGroup.displayName`, цветной кружок по статусу, `recoveryPercent`
в `%`), текст рекомендации сверху, кнопка «Начать тренировку» снизу —
переключает выбранный таб на «Тренировки» и стартует конструктор.

## 5. Экран «Тренировки» — конструктор

**Состояния экрана** (одно view с переключением по состоянию `WorkoutBuilderViewModel.phase`):
- `idle` — пусто, кнопка «Начать тренировку».
- `active` — идёт тренировка: список добавленных упражнений с их подходами,
  кнопка «Добавить упражнение», кнопка «Завершить тренировку».
- `summary` — итог только что сохранённой тренировки (длительность, список
  упражнений/мышц, усилие) с кнопкой «Готово» → возврат в `idle`.

**`WorkoutBuilderViewModel`** (`MuscleLoadApp/Features/WorkoutBuilder/`):
- `start()` фиксирует `startDate = .now`, `phase = .active`.
- `addSet(exercise: Exercise, weightKg: Double, reps: Int)` — добавляет
  подход в текущий черновик (in-memory массив `[SetEntry]`-подобных
  структур, ещё не в SwiftData).
- `finish(perceivedEffort: Int)` — вычисляет `duration = Date().timeIntervalSince(startDate)`,
  создаёт `WorkoutSessionRecord` + `SetEntryRecord` для каждого подхода,
  вставляет в `modelContext`, сохраняет, `phase = .summary`.
- Если приложение закрыто посреди тренировки — черновик теряется (не
  персистится). Осознанное упрощение для v1.

**Выбор упражнения**: минимальный список — `ExerciseCatalog.all` (23
встроенных) с текстовым полем поиска (фильтр по подстроке в `name`), без
своих упражнений (Plan B3) и без техники/картинок.

**Вес тела для упражнений на своём весе**: константа
`bodyweightExerciseIDs: Set<String> = ["pullUp", "pushUp", "crunch"]`
в `WorkoutBuilder`. При выборе такого упражнения поле веса
предзаполняется `UserProfileRecord.bodyweightKg`; если профиль пуст —
показывается однократный алерт с полем ввода веса, значение сохраняется
в `UserProfileRecord` (fetch-or-create по первой записи).

## 6. Вне скоупа Plan B2

Справочник упражнений с поиском/фильтром по мышце/добавлением своих,
техника/картинки упражнений, история прошлых тренировок, графики/
статистика, уведомления, восстановление черновика тренировки после
перезапуска приложения — всё это Plan B3/B4 или явно принятое
упрощение (см. §5).

## 7. CI: экспорт `.ipa`

Финальный шаг плана — добавить в `.github/workflows/app-ci.yml` job,
который после успешных тестов собирает `xcodebuild archive` +
`exportArchive` с `method: development` без реальной подписи
(`CODE_SIGN_IDENTITY=-`, ad-hoc), публикует `.ipa` как артефакт
GitHub Actions. Пользователь скачивает артефакт вручную и ставит на
iPhone через Sideloadly/AltStore (см. обсуждение в диалоге) — сама
установка на телефон вне зоны ответственности CI.
