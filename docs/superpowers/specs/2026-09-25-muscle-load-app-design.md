# ТЗ: приложение расчёта нагрузки и восстановления мышц (iOS)

Дата: 2026-09-25
Статус: черновик на согласовании

## 1. Идея и референс

Приложение для iOS, которое по данным о тренировке (упражнения, подходы, повторы, вес)
автоматически определяет, какие мышечные группы получили нагрузку, насколько сильно,
и когда каждая мышца будет готова к следующей тренировке. Референс — два экрана
стороннего приложения:

1. Итог тренировки: длительность, калории (не реализуем — см. п.9), субъективное усилие
   1-10, список упражнений, бейджи мышц с делением на «основные» / «вспомогательные».
2. Карта восстановления мышц: анатомическая схема тела спереди/сзади, цветовая
   индикация статуса каждой мышцы (рано / можно / готово) + текстовая рекомендация на день.

## 2. Платформа и стек

- **iOS**, SwiftUI, таргет iOS 17+
- **Хранение**: SwiftData, только локально на устройстве. Без бэкенда, без аккаунтов,
  без обязательной сети. iCloud-синхронизация через CloudKit возможна позже как
  доработка SwiftData-моделей, в v1 не делаем.
- **Архитектура**: MVVM. `View` (SwiftUI) → `ViewModel` (`@Observable`) →
  репозитории/сервисы поверх SwiftData.
- **Источник тренировок**: только ручной ввод пользователем. Импорт из Apple Health /
  Apple Watch не делаем.

### Модули

- `WorkoutLogging` — конструктор тренировки (упражнения, подходы × повторы × вес)
- `ExerciseLibrary` — справочник упражнений и шаблонов движений, CRUD для своих упражнений
- `RecoveryEngine` — чистая доменная логика расчёта нагрузки и восстановления,
  без зависимостей от UI/SwiftData напрямую (принимает данные, возвращает результат) —
  за счёт этого легко покрывается unit-тестами
- `Notifications` — планирование локальных уведомлений о готовности мышц
- `Stats` — история тренировок и агрегированная статистика

## 3. Модель данных

- **`MovementPattern`** — шаблон движения. Поля: id, название, список основных мышц
  (`MuscleGroup`), список вспомогательных мышц, коэффициент тяжести (1.0–1.8).
  Единый источник правды по мышцам/тяжести — упражнения на него ссылаются, а не
  дублируют мышцы у себя.
- **`Exercise`** — упражнение. Поля: id, название, ссылка на `MovementPattern`,
  флаг «встроенное / своё», текстовое описание техники (опционально), изображение
  (опционально, до появления пользовательских картинок остаётся пустым).
- **`WorkoutSession`** — тренировка. Поля: дата, длительность, список `SetEntry`,
  субъективное усилие (1-10, вводится по завершении).
- **`SetEntry`** — один подход. Поля: ссылка на `Exercise`, вес (кг), повторы, номер подхода.
- **`MuscleGroup`** — фиксированный enum, 13 значений: Плечи, Бицепс, Трицепс, Грудь,
  Верх спины, Поясница, Пресс и кор, Ягодицы, Квадрицепс, Задняя поверхность бедра,
  Приводящие, Икры, Предплечья.

## 4. Алгоритм нагрузки и восстановления

**Нагрузка одного подхода:**

```
raw_load = вес × повторы × heaviness_coefficient(шаблон движения)
```

Эта величина добавляется каждой мышце из `primaryMuscles` шаблона с весом 1.0 и
каждой из `secondaryMuscles` с весом 0.5.

**Окно восстановления** фиксировано по группе мышц (не зависит от истории
пользователя — MVP-упрощение, адаптивная модель с персональным baseline в v1 не входит):

- крупные группы (квадрицепс, ягодицы, верх спины, грудь) — 72ч
- средние (бицепс бедра, поясница, плечи) — 48ч
- мелкие (бицепс, трицепс, икры, предплечья, приводящие, пресс и кор) — 24ч

**Загрузка мышцы:** суммарная `raw_load` за тренировку нормализуется относительно
порога «полной нагрузки» мышцы → % загрузки в момент тренировки (лёгкая тренировка
не заполняет окно на 100%). Дальше идёт линейный спад загрузки от момента тренировки
к концу окна.

**Статус мышцы** (пороги подбираются при тестировании, стартовые значения):
- 🔴 рано — восстановлено < 40%
- 🟡 можно — 40–85%
- ⚪ готово — > 85%

Полностью офлайн, без сети и без AI-инференса.

**Картинки техники:** для встроенных упражнений источник изображений пользователь
предоставит позже (пришлёт свои). Поле изображения в модели данных опционально и
может оставаться пустым — экран справочника должен корректно работать без картинки
(показывать только текст техники, если он есть).

## 6. Экраны и навигация

Три таба:

1. **Главная** — карта восстановления мышц (анатомическая схема тела спереди/сзади,
   цветовая индикация по каждой группе) + кнопка «Начать тренировку». Шестерёнка —
   переход в настройки уведомлений.
2. **Тренировки** — активная тренировка (добавление упражнений, подходы × повторы × вес),
   по завершении — итоговый экран (длительность, упражнения по мышцам, ввод усилия 1-10).
   Ниже по табу — история прошлых тренировок и простая статистика (объём нагрузки по
   мышцам/неделям).
3. **Упражнения** — справочник с поиском и фильтром по мышце, карточка упражнения
   (техника + картинка, когда появится) + кнопка «Добавить своё».

## 7. Уведомления

Момент готовности каждой мышцы известен сразу при сохранении тренировки (окно
восстановления фиксированное), поэтому уведомления планируются заранее через
`UNUserNotificationCenter` на точное расчётное время. Если несколько мышц становятся
готовы в один день — объединяются в одно уведомление, чтобы не спамить пользователя.

## 8. Тестирование

`RecoveryEngine` не зависит от UI/SwiftData напрямую и покрывается unit-тестами
(XCTest): фиксированные наборы тренировок → ожидаемые % загрузки и статусы мышц.
Остальные сценарии (лог тренировки → карта восстановления → уведомление) проверяются
вручную перед сдачей.

## 9. Вне скоупа v1

- Подсчёт калорий (нет данных с датчиков — пульс/вес не собираем)
- Импорт тренировок из Apple Health / интеграция с Apple Watch
- iCloud-синхронизация между устройствами
- Аккаунты, бэкенд, мультиплатформенность
- Адаптивная модель восстановления с персональным baseline пользователя
- Видео техники выполнения, AI-распознавание упражнений по описанию

## 10. Открытые вопросы

- Источник изображений техники для встроенных упражнений — пользователь пришлёт
  свои материалы позже; до этого справочник работает в текстовом виде.
- Точные пороги статусов восстановления (40% / 85%) и коэффициенты тяжести — стартовые
  значения, подлежат калибровке по ощущениям на реальном использовании.
